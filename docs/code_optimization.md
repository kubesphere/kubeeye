# KubeEye 代码优化文档

## 主要优化内容

本次代码优化主要针对 KubeEye 项目中存在的代码冗余、重复逻辑和混合使用硬编码与YAML定义规则的问题。主要优化包括：

### 1. 规则管理模块化

创建了专用的 `RuleManager` 类，统一处理规则加载、显示和选择的逻辑，以消除组件之间的代码重复。该类提供了：

- 规则加载与过滤
- 规则选择UI组件生成
- 规则标签页的统一处理

### 2. 表单处理优化

- 优化了 `rule_management.py` 中的表单处理逻辑，提取了通用的 `create_rule_form` 函数
- 减少了创建和编辑规则时的代码重复，使代码更易于维护

### 3. 巡检执行流程优化

- 在 `immediate_scan.py` 中使用数据驱动的方式重构了巡检执行逻辑
- 使用配置对象替代重复的代码块，增加了扩展性和可维护性

### 4. Cron 表达式处理优化

- 重写了 `get_cron_description` 函数，使用数据驱动的方法，更易于扩展和维护
- 修复了 `scheduled_scan.py` 中的变量引用错误

## 文件修改概述

1. **新文件**:
   - `/utils/rule_manager.py`: 新增统一的规则管理类

2. **修改的文件**:
   - `/components/common.py`: 使用 RuleManager 重构规则选择功能
   - `/components/scheduled_scan.py`: 修复错误并优化规则选择逻辑
   - `/components/immediate_scan.py`: 数据驱动重构巡检流程
   - `/components/rule_management.py`: 提取表单处理通用逻辑

## 优化效果

1. **减少代码重复**:
   - 消除了规则选择 UI 组件的冗余实现
   - 统一了规则数据处理流程

2. **提高代码可维护性**:
   - 数据驱动的实现更易于扩展和修改
   - 集中式的规则管理降低了修改成本

3. **增强可扩展性**:
   - 新规则类型可以更容易地集成到系统中
   - UI 组件更易于复用和定制

4. **统一规则处理方式**:
   - 无论是硬编码规则还是YAML定义的规则，都通过相同的接口处理
