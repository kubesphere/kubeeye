# Inspector 模块优化文档

## 优化背景

KubeEye 项目的 inspectors 模块中存在以下问题：
1. 代码冗余 - 多个 inspector 类中存在大量相似代码
2. 规则处理逻辑分散 - 每个 inspector 都包含自己的规则解析和处理逻辑
3. 存在空的或者未使用的文件
4. 规则访问模式不一致 - 不同模块使用不同方式访问规则属性

## 主要优化内容

### 1. 创建通用规则处理器类

新增 `RuleProcessor` 类，集中处理规则解析、阈值判断和结果格式化的逻辑：
- 提供安全地访问规则配置的方法
- 标准化处理阈值比较
- 统一结果格式化
- 提供通用的辅助方法

### 2. 重构基础巡检器类

优化 `BaseInspector` 类：
- 添加统一的规则加载方法
- 统一规则应用接口
- 添加通用的规则配置访问方法

### 3. 消除冗余代码

重构各个具体巡检器实现：
- `NodeInspector` - 简化规则应用逻辑，移除冗余代码
- `PrometheusInspector` - 优化指标查询和评估流程
- `OpaInspector` - 改进资源获取和规则评估过程

### 4. 删除空文件

删除了没有实际使用的空文件：
- `node_inspector_unified.py`
- `prometheus_inspector_unified.py`
- `opa_inspector_unified.py`

## 技术改进

### 统一规则处理方式

现在所有巡检器都遵循相同的规则处理流程：
1. 使用通用方法从规则中获取配置值
2. 使用 RuleProcessor 评估规则条件
3. 使用 RuleProcessor 格式化结果

### 代码复用和组织优化

1. **分离关注点**：将规则处理和巡检逻辑分离
2. **提高可维护性**：集中管理共通逻辑，减少重复代码
3. **增强灵活性**：统一的接口使添加新的规则类型或检查方式更加简单

### 向后兼容性

保持了对现有规则格式的向后兼容，包括：
- 同时支持新旧规则格式
- 兼容多种规则配置路径
- 保持结果格式一致性

## 后续优化建议

1. 进一步抽象资源获取逻辑，避免 OpaInspector 中的重复代码
2. 实现更高级的规则过滤机制，允许更灵活地选择规则适用范围
3. 统一异常处理策略，提高错误报告的一致性和可用性
4. 添加规则测试机制，确保规则正确运行
